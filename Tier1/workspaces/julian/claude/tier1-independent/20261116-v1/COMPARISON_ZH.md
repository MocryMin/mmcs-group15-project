# 独立 Tier 1 与 GitHub 仓库 Tier 1 的对比

2026-11-16。对比对象是仓库里 Ran Min（mocry-codex）的 Tier 1 v6 日模型，以及 v7 半小时模型的公布结果。仓库修复后的输入数据复制在 `repo_data/`。金额除特别说明外为 2023 年英镑；仓库原文用 2020 年英镑，换算系数是 1.2006。

## 结论

1. **定性结论一致。** 两边都是零电池、只建电解槽；都是"允许转用"远好于"只用余电"；"只用余电"都有亏损年份。
2. **规模差一个数量级，原因是两个假设，不是方法。** 只用余电：仓库 740 MW，我 40 MW。差距的大头是"谁的余电算数"（740 → 267 MW），其次是电解槽成本和折现率（267 → 60 MW）。数据清洗的差别只占小头（65 → 45 MW）。
3. **方法等价已验证。** 把仓库的数据和假设喂给我的模型，能复现它公布的 739.557 MW 和 £37.712m。
4. **我只用文件夹数据做的清洗，和仓库从源头重建的结果很接近。** 无人买电量占比 21.7% 对 22.3%，97.4% 的日子余缺判断相同。
5. **仓库的半小时结果提示我的"只用余电"偏保守。** 日均值会抵消日内的余缺，这一点我用文件夹里的日数据无法修正。

## A. 数据：我的清洗对仓库的重建

仓库从 Elexon 和 NESO 原始记录重建了全部序列，可以当作检验我估算质量的参照。2020–2025 年：

| 项目 | 我的处理 | 与仓库重建值的差距 |
|---|---|---|
| 需求，每周二（313 天） | 相邻两天均值 | 平均绝对误差 689 MW（约 2.4%），偏低 0.8%。原始值在这些天偏低 17.1% |
| 需求，其余日子 | 不动 | 平均绝对误差 17 MW |
| 电价，未改动的日子 | 乘以 2 | 比值中位数 1.000，91% 的日子相差不到 1% |
| 电价，替换的 338 天 | 相邻两天均值或插值 | 平均绝对误差 £12.7/MWh |
| 电价，六年均值（名义） | £98.1/MWh | 仓库 £98.4/MWh |
| 全国发电，我估算的 125 天 | 回归 | 平均绝对误差 1,250 MW，偏高 164 MW |
| 全国发电，其余日子 | 不动 | 平均绝对误差 166 MW；有 167 天相差超过 100 MW，是仓库另外修正而我没发现的 |

对结果的影响：

| 指标 | 我的数据 | 仓库的数据 |
|---|---:|---:|
| 全国发电超过需求的日子 | 15.1% | 15.9% |
| 加上风电场后超过需求的日子 | 19.9% | 21.0% |
| 风电场无人买电量占比 | 21.7% | 22.3% |

"电价被减半"这个判断得到了完全印证。周二需求的简单替换有不到 1% 的系统偏差，够用。发电的回归估算单日误差不小，但总体无偏。

## B. 我的模型能否复现仓库的结果

用仓库的数据、系统边界、成本（ITM NEPTUNE V，实际折现率 5%，30 年，第 11 和 22 年换堆）、氢净回价 £7.799/kg，金额为 2020 年英镑：

| 情景 | 仓库公布 | 我复现 |
|---|---|---|
| B 供电优先，无销路上限 | 739.557 MW，£37.712m | 739.557 MW，£37.712m |
| A 经济调度，全国销路上限 | 3,631.341 MW，£1,638.660m | 3,632.382 MW，£1,638.538m |
| B，10 吨/天 | 23.424 MW，£2.440m | 25.155 MW，£2.180m |
| A，10 吨/天 | 23.424 MW，£12.681m | 25.155 MW，£12.462m |

前两行吻合。10 吨/天的两行有差别，是因为仓库可以混装 8 种型号去贴合销路上限，我这里只用单一 5.031 MW 机型取整。

## C. 差异分解：从仓库的答案走到我的答案

每一步只改一个假设，其余保持上一步的状态。

**只用余电（仓库的 B）**

| 步骤 | 电解槽 MW | 年净收益 £m |
|---|---:|---:|
| 仓库结果，换算成 2023 年英镑 | 740 | 45.3 |
| 改成只算风电场自己的余电 | 267 | 13.9 |
| 改用我的电解槽成本和 8% 折现率 | 60 | 1.2 |
| 氢价值改为 £9.5/kg（仓库折合 £9.36） | 65 | 1.4 |
| 改用我的数据清洗 | 45 | 0.7 |
| 改为 20 MW 整台、单台最低 4 MW | 40 | 0.7 |

换个顺序看：保留仓库的边界和数据，只换成我的成本和折现率，结果是 231 MW、£420 万。也就是说两个假设各自都能把规模砍掉三分之二左右。

**允许转用（仓库的 A）**

| 步骤 | 电解槽 MW | 年净收益 £m |
|---|---:|---:|
| 仓库结果，换算成 2023 年英镑 | 3,632 | 1,967 |
| 改成只算风电场自己的电 | 780 | 192 |
| 改用我的成本和折现率 | 589 | 113 |
| 氢价值改为 £9.5/kg | 599 | 119 |
| 改用我的数据清洗 | 599 | 118 |
| 改为 20 MW 整台 | 600 | 118 |

这里边界几乎解释了全部差距。仓库把全国 28 GW 的发电都当作可转去制氢的电，再用全国氢消费量（1,559 吨/天）封顶；我的口径下风电场 1,125 MW 本身就是上限。

**两个关键假设的具体差别**

| | 仓库 | 我 |
|---|---|---|
| 谁的电 | 全国发电加风电场，都是客户的 | 只有风电场是客户的 |
| 余电 | 全国发电加风电场超过需求的全部 | 其中属于风电场的部分，不超过风电场出力 |
| 电解槽投资 | £146 万/MW（2020 年价），约合 £175 万（2023 年价）；厂商型号资料 | £200 万/MW；IEA 的 PEM 装机成本 |
| 固定运维 | 约 1.8%/年 | 3%/年 |
| 换堆 | 第 11、22 年固定更换 | 按运行小时计入变动成本 |
| 折现率、寿命 | 实际 5%，30 年 | 实际 8%，25 年 |
| 每 MW 年成本（2023 年价） | 约 £18.1 万 | £24.7 万，另加每 MWh £12 |

## D. 把各自的设计放进对方的世界

| 设计 | 在我的模型里 £m/年 | 在仓库的模型里 £m/年 |
|---|---:|---:|
| 只用余电：我的 40 MW | 0.7 | 5.0（仓库最优 45.3） |
| 只用余电：仓库的 740 MW | **−71.2** | 45.3 |
| 允许转用：我的 600 MW | 118.4 | 376（仓库最优 1,967） |
| 允许转用：仓库的 3,631 MW | 52.2（按风电场上限 1,140 MW 计） | 1,967 |

风险不对称：如果世界像我假设的那样，照仓库的 B 方案建 740 MW 每年亏 £7,100 万；如果世界像仓库假设的那样，照我的方案建 40 MW 只是少赚。这是在边界没有确认之前倾向小规模的理由。

## E. 仓库 v7（半小时）对我的结果意味着什么

仓库 v7 把时间粒度从日改成半小时后，B 的电解槽从 740 MW 升到 1,821 MW，年净收益从 £37.7m 升到 £118.4m（2020 年价），电池仍为零。它给出的原因是：按日求净额会抵消同一天内的余电和缺口，系统层面的正向供需差从每年 2,276 GWh 增加到 5,165 GWh。

这对我的结果有两点含义：
- 我的"只用余电"结论很可能偏保守。文件夹里只有日数据，我没法量化偏多少。
- "不建电池"在仓库的半小时模型里仍然成立，这比我的日模型更有说服力，因为半小时模型能看到日内套利。

## F. 建议小组怎么用这份对比

1. **先确认边界。** 这是最大的分歧，值得直接问导师：余电是算整个系统的，还是只算客户风电场的。文件夹里 `get_data.py` 的算法支持后者。
2. **复核电解槽成本和折现率。** 即使沿用仓库的边界，换成 IEA 的装机成本和 8% 折现率，B 也从 740 MW 降到 231 MW。报告里至少应把这组假设列为敏感性情景。
3. **仓库的模型更成熟，不建议替换。** 它有整数产品目录、半小时时序和最优性证书。我的版本适合作为独立复核和"保守情景"写进报告。
4. **报告里可以直接引用的三句话**：两套独立模型都不建电池；电解槽规模对边界和成本假设高度敏感，范围从 40 MW 到 740 MW；数据里每周二的需求错误若不修正，会把建议放大数倍。
