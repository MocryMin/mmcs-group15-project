## 3. 值得借鉴的高分特征（五个装置 + 三个反面教训）

**(a) 量化让步披露**（Group_23 第 3 页）：先写理想模型，再说明为何在时限内不可解，然后**逐项列出每个近似的实测代价**——5 分钟聚成 30 分钟（规模 ÷6）、帕累托剪枝（÷60，剩 100–200 部片/周）、求解器设置（5% gap、600 s）、实际用时（1–2 分钟/周）、以及唯一失败（超时后 6.4% gap）。这正是今年题面"technical validation"要的东西。

**(b) 两阶段随机投资 + 精确/启发式可扩展性表**（74 第 8–9 页表 3）：一阶段整数投资、二阶段情景加权连续运营；表中列实例规模（10→1000 节点）、变量/约束数、目标值、求解时间，失败写 `N/A`。对应我们：全年 MILP 精确解 vs 滚动 LP/启发式的对照，以及"为何在压力测试里降级"。

**(c) 分阶段验证阶梯 + 事后批次 + 信息受限情形**（Group_8 第 7–10 页）：同一实例、同一 KPI 表，每加一个机制跑一遍（baseline→+调整→+校准），再把冻结参数放到更晚时期（out-of-time），再限定为"决策时只能看到的信息"。对应我们：不投资 → 朴素规则 → 优化调度 → 不完美预见，四行同一组 KPI。

**(d) 切换点/保留价格分析**（Group_23 第 6–7 页）：从模型自身的影子价格推出"低于此价不卖"的规则，并加一节"可能的反驳"主动把最弱参数摆出来。对应我们的三个阈值：循环条件 $p_{sell}/p_{buy}>1/0.9$、氢的电力等价 £169.95/MWh、电解槽 CAPEX 1.0–1.65 m£/MW 的临界容量，以及电池 FOM 2.9% vs 表头值的临界点。

**(e) 一页决策块**（74 第 9–10 页）：最坏情形运营成本上界（两条路线 3.11 h → 燃料 £5,000 + 人工 £17,520 = £22,520/年）→ 排序的资金来源（票款 → 广告 → 补贴）→ 回收期 → 真实底图上的点位图。对应：运营成本上界 → 收入栈（套利 → 容量/辅助服务 → 补贴）→ 回收期/NPV → 资源与网络图"。

**反面教训（同样值分）**：
- **Group_10**：宣称 robust，但约束把 £ 与 % 混算（量纲不一致），±£50k 的公平带宽无来源，且**完全没有求解证据**（无模型规模、无求解器、无运行时间）——只到低 Merit。

- **全员通病**：**没有任何一份对决策参数做敏感性或盈亏平衡**（74 与 Group_23 只做到部分）。这是最容易超越往届的地方，也是你我两轮审核里反复指出的同一件事。

## 5. 对我们 11-27 交付的直接含义

1. **往届高分不来自"研究更全"，而来自"模型被证明跑得动、被验证、被用来给出决策阈值，并把局限写在纸面上"。** 这与我对 v1.1 的审核结论互相印证：v1.1 的研究深度已超过这些往届报告的证据部分，缺的正是它们据此得分的那部分。
2. **篇幅按 14–18 页规划**，图 6–8 张：①盈余/价格/需求的分布或时序；②最优容量—目标函数（边际价值）曲线；③二维临界图（电解槽 CAPEX × 氢价）；④tornado；⑤A0/A1/B0/B1 对比；⑥回测或事后检验；⑦（2B）季节性 SOC 轨迹 或（2A）技术组合图。表 2–4 张：参数与来源、情景定义、KPI 汇总。
3. **必写一节"计算可行性"**：变量/约束数、Xpress 求解时间、MIP gap、失败实例与降级策略（滚动 LP/启发式），失败就写 `N/A`。
4. **必写"切换点"表**：把阈值算出来，而不是定性讨论。
5. **必写"信息受限"版本**（若做随机/滚动）：只用决策时可见信息重跑，报 mean ± SD。
6. **明确不要照抄的三点**：G10 的量纲混算；G8 的零引用；74 的"把二阶段项按物理量直接加进目标"（加权重即可修好）。
