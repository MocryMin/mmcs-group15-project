## 2. 真正强的地方（应当保留）

1. **单位与口径纪律**：£/kW H2 HHV 与 £/kW_e 的 1.4 倍陷阱、EUR2020 与 nominal USD2024 的混用风险、55.9 kWh/kg 含全系统辅助用电、"不要重复计费"（PCS/EPC、逆变器更换、堆替换 vs 每 kg 储备、补贴不叠加）——这些是课程里最容易失分的地方，v1.1 基本都堵住了。
2. **冲突保留而非强行归一**：电池 FOM 的 2 倍矛盾保留双情景并说明"不是机构勘误"；这正是评分点"区分数据支持与建模假设"。
3. **A/B 方案结构清楚**：A/B 共用会计、四种比较（A0/A1/B0/B1）、B 的可执行解释（$q_t=\min(G_t,D_t)$，且必须单独追踪"当期发电直售"防止电池放电替代政策义务）、无免费初始电量、跨断档不拼日期、design/validation/test 时序与 oracle 命名纪律。这套结构比 Baseline 1103 原文更可执行。
4. **控制决策可审计**：20 条 accept/reject/conditional 记录、reopen 触发器、发布与采纳分离、并明确"发表不等于小组同意"。
5. **诚实披露**：三个 worker 的分析独立但取源由 R1 单一浏览器代理转发，v1.1 自己写明了"检索未三次独立重复"。没有把代理说成独立联网验证。

结论：作为**研究备忘录**，这是 A 级；作为**课程提交物**，它目前只完成了基础设施。

## 4. 我认为需要处理的问题（按影响排序）

**R-1（严重）研究过重、模型为零，且剩余时间不足。** 报告 11-27 交、11-30 路演；v1.1 产出中约 60% 是治理性文件（RUN/VALIDATION/REVIEW_DECISIONS/MANIFEST，20 条决策对应约 7 个参数）。这些对评分边际贡献很低。建议立即把控制层压缩为附录一页，把人力转到模型。

**R-2（方法，重要）"逐日时序"的时间处理既不是 Tier1 的简化口径，也不是 Tier2B 的完整时序。** 题面原文："Tier 1 models should use a simplified treatment of time – detailed chronological operation of storage is not required at this stage"；chronology 是 2B 的内容。v1.1 把"每日只充或只放、通量≤一个可用窗口、初末库存相同"作为 Tier1 主模型（BL-04/BL-11 也已如此）。后果有两面：一方面它是保守的（可辩护），另一方面它把 2B 的核心机制（跨日 SOC 传导、季节性）提前消耗掉，等做 2B 时"升级"幅度变小。建议：Tier1 用聚合期（月/季）能量平衡 + 效率与容量约束，Tier2B 再上逐日 SOC 与 28 段断档处理；v1.1 的日规则作为 2B 的子情形保留。

**R-3（数据，重要且 v1.1 漏掉）107 个"全部可调度燃料=0 MW"的日期。** 我在独立调研中发现并复现：2022-10-17 至 2026-08-03 共 107 天，核/气/煤/油/生物质/水电/抽蓄/其他全部为 0 MW，当日总发电仅 1,450–17,614 MW（需求中位约 27,500 MW）。剔除这 107 天与 2022-08-02 需求异常后，缺口从 160.30 降到 111.41 TWh，盈余几乎不变（40.63→40.01 TWh）。这不是"罕见极端值"，是**报告伪影**：燃料明细缺失但总量仍在，说明分项表在那些日子没有分发。它直接影响 B 政策：B 强制 $q_t=\min(G_t,D_t)$，在这些日子会把几乎全部发电判给直售、电池无电可充，系统性压低 B 下储能价值、并抬高缺口统计。必须在 run manifest 里作为 SA-DQ 单独跑一遍并披露，不能当作真实稀缺。

**R-4（参数，重要）电解槽 CAPEX 两条证据路线差 1.8 倍，且被当成"已解决"。** v1.1 现代 IEA 路线 1,270–1,651 GBP2020/kW_e，旧 BEIS 路线 672–1,329（中值 816）；同一份文件里两个口径差约 1.8 倍，而 v1.1 只把旧值降为"legacy sensitivity"。这个跨度足以单独决定"要不要建电解槽"，应该是标题级敏感性（CAPEX × 氢价 的二维临界图），而不是脚注。附带的次级问题：现代情景的堆替换仍用旧 BEIS 绝对代理（489.61 GBP2020/kW_e，第 11/22 年），v1.1 自己已标注"跨模型代理、独立不确定"——但这正是 30 年现金流里最敏感的一项，同样需要二维呈现。（我自己的独立结论落在低端：BEIS 2020 中值 ×1.25 上推 = £1.04 m/MW_e(2026)≈£0.79 m/MW_e(2020)；**两轮不一致，这一点没有共识**。）

**R-5（题面前提，缺失）没有定义"上一家咨询公司的简单方案"。** 题面开篇："The client has already received a proposed solution from another consultancy but was not satisfied… challenge the assumptions behind a simple solution"。评分要求"为什么比简单策略好"。Baseline 1103 的 A0/B0 是"不投资"，不是那个被质疑的简单方案。建议显式构造两个对照：(a) 不投资；(b) 朴素规则（例如按日均价、每天满窗口一次循环的 50 MW 电池），并量化 LP 相对它们的增量——这几乎是白送分的对比实验。

**R-6（决策分析，缺失）没有阈值/临界点。** 三个已经可算、且咨询口吻很强的数（来自我的独立调研，属我的结论，不是 v1.1 的）：
- 电池套利必要条件 $p_{sell}/p_{buy} > 1/0.9 = 1.111$；同价循环每 MWh 净亏 £4.82；
- 氢的电力等价价值：£9.5/kg ÷ 55.9 kWh/kg = £169.95/MWh 输入电（这是"氢何时打得过直售"的判据）；
- 电池 FOM 取 2.9% 还是表头值，等于把年固定成本从 €12,528 变成 €25,056（3 MWh 单元），直接改变投资临界容量。
把这三条画进一张"建议对什么敏感"的图，比多写十条决策记录更能拿分。

**R-7（财务）5% 实质贴现 + GBP2020 是可辩护选择，但与题面"ROI is a factor"对接不足。** 题面点名 ROI；v1.1 用年度等价净收益与 NPV，未给 IRR/回收期/投资回报的呈现方案（BL-14 提了 payback 但 v1.1 参数包没有）。另外我这一轮选 7%/GBP2026，两轮不同——两者都不是证据，**这也是小组必须先定一个报告基准的原因**，否则 A0–B1 四个方案的跨文件比较会失真。

**R-8（前瞻，若选 Tier2A 则为重大缺口）Tier2A 完全空白。** 没有 RE PD 项目管道、没有分技术 CAPEX/LCOE、没有从所给燃料数据估容量系数、没有并网/土地成本。若团队倾向 2A，需要现在就补；若选 2B，v1.1 的研究反而正好用得上（时序、断档、SOC、季节性）。

**R-9（工程卫生，次要）** `FIRST_PASS/` 与正式目录内容重复（体积翻倍）；`prices_gbp2020.csv`（146 KB 派生序列）应标注"派生、非原始"。不影响评分，但评审读起来会怀疑版本控制。

## 5. 对"缺失 / 可自指定 / 需调研"分类的独立意见

v1.1 的分类大体正确，我建议三处改动：

1. **可自指定但被当成"已调研关闭"**：E-03 购电（设为 0 是选择，不是证据；应给"允许购电 + 附加费 a"的敏感性，并把盈亏平衡附加费 $a^*=0.9p_{sell}-p_{buy}$ 作为输出）、E-06 弃电补偿（0 是选择）、H-04 承购上限（0/2k/10k/50k kg/日 是分析者情景，应明说是"决策变量上界"而非需求估计）。
2. **需调研但被过早关闭**：E-05 价格影响（日内/半小时数据不可得，但可用"可承受的价格弹性阈值"给出结论边界）；H-05 储运（BEIS T&S 报告有 0.26–3.56 £/kg/100 km 的现成数，够做一个"是否需要储运"的门槛判断）。
3. **完全缺失**：题面的"简单方案对照"、Tier2A 研究、以及**报告/路演层面的评分要素**（Q 类问题 v1.1 标为"未解决"，但其中"报告字数/附录/封面""路演时长"是同学可直接向教师确认的操作性信息，不该悬置到 11 月底）。

## 6. 结论：这份提案是否"利于拿高分"

- **作为研究**：是。它建立了一个可实例化、单位干净、冲突透明的参数界面，比我见过的多数同级研究扎实；把这些写进报告附录，会在"clear assumptions / appropriate use of data"两项上加分。
- **作为提交物**：不是。它现在只完成了前置条件。真正决定分数的四件事——一个跑得动、验证过、有可视化、能回答"投多少/为何优于简单方案/什么会改变建议"的模型，以及 Tier2 的深度——都还是零。
- **最大风险**不是研究质量，而是**重心与时序**：v1.1 的完成方式（20 条决策、闭合研究、停止搜索）会给团队一种"研究已就绪"的错觉，把接下来两周继续投在参数润色上；而 11-27 之前必须完成的是模型、验证、敏感性图谱和咨询叙事。
- **我的建议**（按周）：①本周定 Tier2（我倾向 2B，因为 v1.1 的时序研究正好可用，且 2B 的"韧性/随时间"叙事更贴题面的 sustainability 定义）；②同步实现 Tier1 聚合期 LP，把 R-5 的两个简单对照跑出来；③把 R-3、R-4、R-6 做成三张"什么会改变建议"的图；④控制层压缩为一页附录，不再新增治理文件；⑤若走 2A，第一周就要补 Tier2A 的发电侧数据研究，否则来不及。
